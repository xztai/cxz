# Backend etheyl

- Go 1.27.4. Before editing Go, run the installed Modern Go Guidelines CLI (`sh <skill-dir>/scripts/run-tool.sh list --file-path <file>`). Portable pinned equivalent: `go run github.com/JetBrains/go-modern-guidelines@v0.1.1 list --go-version 1.27`. Follow version-specific guidance, including encoding/json/v2, method-aware ServeMux and t.Context().
- `cmd/etheyl`: API, worker, migrations, admin CLI. `internal/httpapi`: HTTP boundary; `internal/auth`: passwords/tokens; `internal/config`: environment; `internal/mailqueue`: transactional mail outbox. `internal/store`: **generated sqlc**, never edit manually.
- PostgreSQL is the source of truth. Change `queries/*.sql`, run `make generate` from the repository root. Migrations are ordered, reversible goose SQL in `migrations/`; never change an already deployed migration.
- Business mutations spanning users, tokens, sessions and mail must use a single transaction with `store.New(tx)`. Lock the user before consuming a token or creating a session; preserve this lock order. Always roll back on failure.
- Wrap internal errors; return only stable Russian messages and API error codes to clients. Structured logs must not include passwords, cookies, email links, tokens or request bodies.
- Hash passwords with bounded Argon2id parameters and random salts. Store only SHA-256 digests of cryptographically random sessions and action tokens. Sessions are server-side, expiring, revoked on reset; user roles are not mutually exclusive.
- Every unsafe HTTP request requires exact Origin and cookie/header CSRF validation, including login. Rate limits are shared in PostgreSQL. Trust proxy headers only when explicitly configured; Compose exposes only the proxy.
- Duplicate registration returns 409 `email_exists`; it must not change the existing account/token or enqueue email. Verification preview returns only the email for a valid token without consuming it. Confirmation consumes the token, verifies the user and creates a session in one transaction; set the HttpOnly cookie only after commit.
- Public accounts expose `nickname`, not the legacy `name` column. Nicknames are 3–30 ASCII letters/digits/`_`/`-`; reject dots, whitespace and Unicode before lowercasing. PostgreSQL enforces canonical format and uniqueness; return 409 `nickname_exists` on collision. Login remains email-based. Legacy accounts receive `user-<id>` through migration 00002; keep the original names for rollback. Admin CLI uses `--nickname`.
- A reset to the current password returns 422 `password_unchanged`. Compare under the user row lock; rollback must preserve the action token and all sessions. Consume/check the token before comparison so concurrent replays still return `invalid_token`.
- Before completion: `gofmt -w cmd internal`, `go test ./...`, `go vet ./...`, `make lint` (root, golangci-lint v2.15.0). Integration tests require `TEST_DATABASE_URL` and a dedicated empty database; they run goose migrations automatically. Run `make test-integration` and `make e2e` with Compose for auth changes.
- Generation: `go run github.com/sqlc-dev/sqlc/cmd/sqlc@v1.31.1 generate`. Goose v3.30.0 is pinned in go.mod. Frontend contract lives in `../docs/openapi.yaml`; keep handlers, generated frontend types and contract aligned.
