# Лента, обсуждения и аналитика — этап 5

Персональная лента находится в `/account/feed`, аналитика автора — в
`/account/analytics`. Переходы доступны из личного кабинета. Лайки и плоские
комментарии находятся под опубликованным постом.

## Лента и доступ

В ленту входят опубликованные посты авторов с действующим оплаченным доступом:
`starts_at <= now()`, `expires_at > now()`, без отзыва grant. Отключение продления
не скрывает уже оплаченный период. Истёкшие, будущие и отозванные grants не
попадают в ленту. Блокировка автора скрывает его публикации.

Лента возвращает только заголовок и отдельно заданный публичный анонс. Для
публикации выше оплаченного уровня показывается предложение выбрать старший
уровень; закрытые текст и файлы по-прежнему проверяются отдельными API-запросами.
Общий SQL-предикат `post_readable` используется для текста, медиа, ленты и обсуждений.

Пагинация — курсор по `(published_at DESC, id DESC)`, по 24 записи. Вставка новых
постов не сдвигает следующие страницы; одинаковое время публикации разрешается ID.
Курсор не является разрешением на доступ: подписка проверяется на каждом запросе.

## Лайки и комментарии

Действия доступны только авторизованным подтверждённым пользователям с доступом
к опубликованному посту. Черновики не имеют обсуждения даже для владельца.
Обсуждение также требует входа; у гостя под открытым постом отображается приглашение.

- `GET /api/v1/posts/{id}/discussion` — счётчики и до 24 комментариев, новые первыми;
  `before` продолжает список по ID, без offset.
- `PUT /api/v1/posts/{id}/like` — поставить лайк; повтор не создаёт дубль.
- `DELETE /api/v1/posts/{id}/like` — убрать свой лайк; повтор безопасен.
- `POST /api/v1/posts/{id}/comments` — обычный текст длиной 1–2000 символов после
  удаления крайних пробелов. HTML/Markdown не интерпретируются; ответов и веток нет.
- `DELETE /api/v1/posts/{id}/comments/{commentID}` — удалить только свой комментарий.
  Это разрешено и после окончания подписки/снятия поста с публикации, чтобы
  пользователь мог убрать собственный текст; удаление не раскрывает содержимое.

Для мутаций обязательны точный Origin и CSRF cookie/header. Проверка пользователя,
доступа и запись проходят в транзакции; строка опубликованного поста блокируется
на время изменения. Уникальный ключ `(post_id,user_id)` исключает дубли лайков.
Создание комментариев дополнительно ограничено 20 попытками на аккаунт за 15 минут,
помимо общего IP-лимита. При удалении поста лайки и комментарии удаляются каскадно.
Заблокированные аккаунты не видны в комментариях и счётчиках.

## Аналитика

`GET /api/v1/me/analytics?from=YYYY-MM-DD&to=YYYY-MM-DD` использует текущего автора
из серверной сессии. Передать чужой ID автора нельзя. Без профиля возвращается
`profile_required`; интерфейс предлагает оформить профиль.

Обе даты включаются, границы — календарные сутки UTC. По умолчанию — последние
30 дней с текущим днём; допустимо 1–366 дней. Платежи считаются по `completed_at`
(дата серверного подтверждения), `status='succeeded'` и непустому ID провайдера.
Сумма берётся из неизменяемой оплаченной попытки в копейках, а не из текущей цены
уровня. Ожидающие, отклонённые и требующие проверки попытки исключены. Уникальность
ID провайдера и идемпотентные терминальные переходы предотвращают повторный учёт.

Результат содержит итоговую сумму, число платежей, каждый день периода (в том числе
нулевые), текущие активные grants и распределение по уровням. Эти запросы читают
один согласованный snapshot PostgreSQL. Активные подписки — срез на момент запроса,
независимый от выбранного периода платежей; отменённые продления и архивированные
уровни с ещё оплаченным доступом учитываются. Будущие, истёкшие, отозванные grants
и заблокированные подписчики исключены.

Все денежные показатели явно тестовые. График использует shadcn-svelte Chart и
SVG-компонент LayerChart, загружаемый отдельно на экране аналитики. Данные доступны
также в таблице по дням; ошибка загрузки графика не скрывает суммы и таблицу.

## Проверки

```sh
make generate
make lint
make test-integration
make test-restore
cd frontend
pnpm check
pnpm build
pnpm peers check
pnpm check:mcp
pnpm test:unit
pnpm format:check
```

Интеграционные тесты проверяют действующие/истёкшие/будущие/отозванные grants,
старший уровень, отсутствие закрытого текста, страницы с одинаковыми timestamps,
параллельные лайки, собственное и чужое удаление комментариев, блокировку,
границы UTC, нулевые дни, дубли платежей, зафиксированные суммы и изоляцию авторов.

Браузерные тесты требуют отдельный Compose-проект с суффиксом `-social-tests`.
Fixture создаёт grants и контрольные подтверждённые платежи только через БД
этого тестового проекта; публичного HTTP API выдачи подписок нет. Ключи ЮKassa не
используются и внешних списаний нет.

```sh
# Из корня, свежие тестовые volumes; пользовательское окружение не затрагивается.
APP_PORT=18085 MAILPIT_PORT=18035 APP_ORIGIN=http://localhost:18085 \
  YOOKASSA_SHOP_ID= YOOKASSA_API_KEY= \
  docker compose -p etheyl-stage5-social-tests up --build --wait
cd frontend
E2E_BASE_URL=http://localhost:18085 MAILPIT_URL=http://localhost:18035 \
  E2E_SOCIAL_PROJECT=etheyl-stage5-social-tests pnpm test:e2e:social
```

Desktop/mobile сценарий проверяет закрытый пост до оплаты, персональную ленту и
пагинацию после fixture-оплаты, лайк/снятие, экранирование HTML, отправку/удаление и
пагинацию комментариев, контрольную сумму аналитики, настоящий SVG-график, таблицу
и смену периода. CI запускает отдельную группу `social` на свежем Compose.
