# etheyl

MVP сервиса авторских подписок: авторизация, профили авторов, каталог с поиском, уровни подписки, публикации с приватными медиа, кабинеты аккаунта и администратора. Один аккаунт может использоваться автором и подписчиком. Оформление подписок, платежи и модерация пока не реализованы.

## Запуск

Нужны Docker Engine с Compose v2+ и Python 3 для генерации локальных секретов. Для проверок вне Docker — Go 1.27.4, Node 26.13.0 и pnpm 12.18.0

```sh
make init
make up
```

`make init` создаёт `.env` со случайными паролями ролей PostgreSQL и MinIO, ключом шифрования outbox и правами `0600`. В существующий файл дописывает только отсутствующие настройки, сохраняя прежние значения. Первая сборка MinIO занимает несколько минут. `make up` собирает образы, выполняет goose-миграции и ждёт готовности сервисов.

- Приложение: **http://localhost:8080**.
- Локальная почта: **http://localhost:8025** (Mailpit).
- Готовность API: `GET http://localhost:8080/api/v1/health`.

Регистрируйтесь через интерфейс с уникальным никнеймом: 3–30 символов, латинские буквы, цифры, `_` и `-`, без точек и пробелов. Никнеймы сохраняются в нижнем регистре; `Author` и `author` считаются одним никнеймом. Он используется в адресе профиля автора `/authors/<nickname>`. Вход выполняется по email.

Откройте письмо в Mailpit и подтвердите email кнопкой на странице из письма. Страница показывает подтверждаемый адрес; после подтверждения автоматически создаётся сессия и открывается личный кабинет. Повторная регистрация занятого email или никнейма сразу возвращает ошибку и не отправляет новое письмо. Кнопка повторной отправки подтверждения находится только в карточке «Проверьте почту»: после регистрации или попытки входа с правильным паролем в неподтверждённый аккаунт. Для подтверждённых аккаунтов она не показывается.

После регистрации и входа с правильным паролем в неподтверждённый аккаунт интерфейс открывает `/auth/check-email`. После отправки письма повторная отправка доступна через 60 секунд; таймер сохраняется при обновлении страницы. На этом же экране можно исправить email, указав текущий пароль. Аккаунт и никнейм сохраняются, письмо отправляется на новый адрес, прежняя ссылка становится недействительной. До подтверждения сессия не создаётся. Пароль хранится только в памяти формы; в `sessionStorage` сохраняются адрес и состояние повторной отправки. Старый `/auth/resend` перенаправляет на общий экран; отдельной ссылки подтверждения на странице входа нет.

Восстановление пароля открывается со страницы входа или из личного кабинета. Текущий пароль нельзя установить повторно: API вернёт ошибку, сохранив ссылку для следующей попытки и действующие сессии. Письма обычно приходят в течение секунды; при временном сбое SMTP worker повторяет отправку с задержкой.

Миграция `00003_secure_outbox.sql` удаляет ожидающие письма старого plaintext-формата: после обновления запросите такие письма заново. Уже доставленные ссылки продолжают действовать.

Миграция `00002_nicknames.sql` назначает ранее созданным аккаунтам уникальные никнеймы `user-<id>`. Их email, пароли, статусы и сессии сохраняются; прежнее имя остаётся в БД для обратимости миграции.

Открывайте именно `localhost:8080`: Origin запросов должен совпадать с `APP_ORIGIN`. При смене адреса меняйте `.env` и пересоздавайте сервисы. Конфигурация Compose предназначена для локальной разработки: HTTP, почтовый перехватчик, порты привязаны к loopback. Порядок перехода к HTTPS, внешнему SMTP, backup/restore и эксплуатации описан в [docs/operations.md](docs/operations.md).

```sh
docker compose ps
docker compose logs -f api worker
make down
```

Остановка сохраняет volumes `postgres_data` и `minio_data`. PostgreSQL, API и MinIO не публикуют порты на хост; консоль MinIO отключена. Одноразовый `storage-init` создаёт bucket `etheyl-media` (или `S3_BUCKET`) и удаляет публичную policy перед запуском API. Изображения доступны через API, прямой анонимный доступ к bucket закрыт.

## Первый администратор

После запуска выполните в терминале:

```sh
docker compose exec api etheyl admin --email admin@example.com --nickname admin
```

CLI запросит пароль без отображения (минимум 12 символов), создаст подтверждённый аккаунт администратора. Если email или никнейм уже занят, команда завершится ошибкой; существующие аккаунты она не повышает. Затем войдите через обычную форму по email и откройте `/admin`. Доступ проверяет Go API. Публичная регистрация не принимает признак администратора.

Для автоматизации есть `--password-stdin`: пароль передавайте через stdin, не через аргументы командной строки. Миграции можно безопасно повторить: `docker compose run --rm migrate`.

## Авторизация и ограничения

Пароли: Argon2id, 64 MiB, 3 прохода, 2 потока, случайная соль. В таблицах сессий и action-токенов хранятся SHA-256-хеши случайных 256-битных значений. Сессия действует 30 дней, подтверждение email — 24 часа, сброс пароля — 1 час. Восстановление отзывает все сессии и сбрасывает счётчики неудачных входов для текущей пары IP/email и риска email; выход отзывает текущую сессию. Отклонённый сброс сохраняет счётчики. Cookie HttpOnly, SameSite=Strict, host-only; для HTTPS обязательны Secure и префикс `__Host-`.

Каждый POST требует точный Origin и совпадение CSRF-header с HttpOnly-cookie, включая регистрацию и вход. БД хранит общие для экземпляров API лимиты: 60 POST/IP за 15 минут, 5 регистраций/IP, 10 неудачных входов на пару IP/email, 3 запроса письма на пару IP/email/тип. Успех очищает счётчик пары; повышенный риск email добавляет ограниченную задержку, сохраняя вход с другого IP. Глобальный бюджет 3 письма/email/тип молча объединяет лишние запросы и сохраняет последнюю ссылку. Cookie и токены не попадают в журналы; ссылки в письмах используют fragment и не отправляют токен в URL HTTP-запроса. Пароли не обрезаются и не нормализуются.

`POST /auth/change-unverified-email` принимает `email`, `newEmail` и текущий `password`, требует Origin и CSRF и разрешён только для неподтверждённого незаблокированного аккаунта. Смена адреса, замена action-токена и постановка письма в очередь выполняются одной транзакцией под блокировкой пользователя. При конфликте адреса или ошибке очереди сохраняются прежний email и ссылка. Лимит — 5 попыток/IP/15 минут плюс общие ограничения неудачного входа.

Каждый запрос ограничен deadline 5 с; SQL имеет statement_timeout 4 с и lock_timeout 2 с. Лимит четырёх вычислений Argon2 не удерживается при ожидании SQL или чтении тела. Каждый браузерный fetch имеет собственный таймаут 10 с.

Пользователь, токен и письмо создаются в одной транзакции. Тело outbox зашифровано AES-256-GCM, ключи вынесены в `OUTBOX_KEYS` отдельно от БД. API не может читать тела очереди; worker имеет только необходимые права, мигратор — отдельную роль владельца схемы. Worker выбирает письма через `FOR UPDATE SKIP LOCKED`; успешные удаляет, неуспешные откладывает, максимум 8 попыток, затем явное состояние failed. Актуальное письмо можно повторить через `docker compose exec worker etheyl requeue-mail --id 123`; просроченные и использованные ссылки не отправляются. Внутренний `/api/v1/mail/status` worker показывает backlog/failed/heartbeat, отдельно от liveness. SMTP имеет семантику at-least-once: после аварии письмо может повториться, но токен останется одноразовым. Завершённые сессии, просроченные токены/лимиты и старые записи outbox очищаются worker. Время в БД — `timestamptz`, инфраструктура работает в UTC.

Настройки backend: `DATABASE_URL`, `OUTBOX_KEYS`, `REQUEST_TIMEOUT`, `APP_ORIGIN`, `HTTP_ADDR`, `COOKIE_SECURE`, `TRUST_PROXY`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_INSECURE`. По умолчанию SMTP требует TLS; Compose явно включает локальный режим. `TRUST_PROXY=true` допустим за доверенным reverse proxy: Caddy перезаписывает `X-Real-IP`, а API не опубликован наружу. В ручном dev-запуске оставляйте `TRUST_PROXY=false`.

Шрифты поставляются только в WOFF2 для Latin/Cyrillic; `pnpm build` проверяет бюджет шрифтов 150 КБ, JavaScript 130 КБ gzip (включая отдельные модули редактора и чтения постов) и CSS 20 КБ gzip для всей client-поставки.


## Профили авторов и уровни

- `/account/profile` — уникальный адрес (никнейм аккаунта), публичное имя, описание,
  аватар и обложка. Первое сохранение публикует профиль в каталоге. Изменение
  никнейма меняет адрес `/authors/<nickname>`; старый адрес перестаёт работать.
- `/authors` — каталог с поиском по имени, никнейму и описанию. 24 автора на страницу.
- `/authors/<nickname>` — публичный профиль и активные уровни. Email и ключи S3
  не входят в публичные ответы. Заблокированные авторы и их изображения скрыты.
- `/account/tiers` — создание, редактирование, порядок и архив. Цена — целое число
  копеек RUB (0–100 000 000); интерфейс принимает рубли с точностью до копейки.
  Максимум 50 активных уровней. Новый уровень получает позицию выше всех имеющихся,
  включая архив. Старший включает младшие у того же автора (`TierIncludes`).
- Позиция уровня с `used_at` неизменна; такой уровень архивируется вместо удаления.
  Неиспользованные уровни можно переставлять, архивировать или удалять. Архив
  скрыт публично и сохраняет позиции и историю доступа. Архивирование необратимо.
  Публикации/подписки устанавливают `used_at` триггером в той же транзакции;
  API сохраняет порядок блокировок user → creator; публичного API для изменения признака нет.
- Все изменения привязаны к серверной сессии владельца и защищены Origin/CSRF;
  переданный ID другого автора не даёт доступа.

Go использует `minio-go/v7`. Изображения принимаются сырыми байтами через
`PUT /api/v1/me/profile/images/{avatar|cover}`. Поддерживаются JPEG, PNG и WebP,
до 5 МиБ, 8192 пикселей по стороне и 16 миллионов пикселей. MIME должен совпадать
с реальным форматом; полное декодирование и повторное кодирование удаляют метаданные
и посторонний хвост. WebP сохраняется как PNG. PostgreSQL хранит ключ, MIME, размер,
ширину, высоту и SHA-256 сохранённого объекта. При замене удаляется прежний объект;
при ошибке записи БД новый объект удаляется компенсирующей операцией.

Для Go вне Compose задайте `S3_ENDPOINT` (host:port), `S3_ACCESS_KEY`, `S3_SECRET_KEY`,
`S3_BUCKET=etheyl-media`, `S3_SECURE=false` для локального HTTP. Перед стартом выполните
`etheyl storage-init`. Compose передаёт эти настройки сам; порты MinIO наружу не открыты.
Миграция `00004_creators.sql` создаёт таблицы и DB-защиту истории используемых уровней.

Проверки: PostgreSQL integration tests покрывают владение, коллизии адресов,
иерархию, архив, порядок и метаданные; unit tests — небезопасные изображения;
Playwright проверяет оформление профиля, реальные загрузки MinIO, уровни и поиск
в desktop/mobile, затем прежние сценарии восстановления аккаунта.


## Публикации и приватные файлы

`/account/posts` — кабинет автора: черновики, редактирование, публикация, возврат в
черновики и удаление. Сначала сохраните профиль автора. Опубликованные посты видны
на `/authors/<nickname>`, чтение — `/posts/<id>`. У поста есть отдельный публичный
анонс: API никогда не получает его обрезкой закрытого текста.

Текст хранится как CommonMark и отображается серверным goldmark без произвольного
HTML и опасных схем ссылок. Пост доступен всем либо с минимального уровня у этого
автора. Старшие уровни включают младшие по позиции, независимо от цены. Для доступа
нужна действующая подписка: начало уже наступило, срок не истёк, отзыва нет.
Архивирование уровня сохраняет доступ ранее выданных подписок. Автор видит свои
черновики и закрытые посты. Заблокированный автор скрыт целиком.

Без доступа API возвращает заголовок и публичный анонс с метаданными; поля
`bodyMarkdown`, `bodyHtml`, `media` полностью отсутствуют. Черновики посторонним
возвращают 404. Доступ проверяется повторно для каждого оригинала, миниатюры,
HEAD и Range, до условных HTTP-ответов. API и SSR используют no-store; закрытый
контент не получает общих кэшей или прямых/подписанных ссылок MinIO.

Файл загружается сырыми байтами через `POST /api/v1/me/posts/<id>/media` с query
`kind=image|audio|video|attachment`, `filename` и обычной Origin/CSRF-защитой.
Максимум **104857600 байт (100 МиБ, в интерфейсе 100 МБ)** на каждый файл.
API ограничивает поток и сохраняет его во временный файл, не загружая 100 МБ в RAM.
Оригиналы всех типов сохраняются побайтно, без транскодирования. Для JPEG, PNG,
GIF и WebP до 8192 пикселей по стороне и 16 Мп создаётся отдельная PNG-миниатюра
до 640 пикселей. Аудио: MP3, WAV, Ogg, WebM, MP4/M4A, FLAC, AIFF, MIDI; видео:
MP4, WebM, Ogg. Реальное воспроизведение зависит от кодеков браузера. Любой другой
формат можно загрузить вложением. Вложения, включая HTML/SVG, всегда скачиваются
с `Content-Disposition: attachment` и `application/octet-stream`.

У загрузки заранее сохраняется запись `uploading`; только после успешной записи
оригинала и миниатюры она становится `ready`. Удалённые и отсоединённые файлы сразу
теряют доступ. Worker примерно раз в минуту удаляет отсоединённые объекты, зависшие
загрузки старше часа, незавершённые multipart-загрузки и несвязанные объекты старше
часа под `posts/` и `profiles/`. Сбой удаления сохраняет запись для повторной попытки. API отдельно убирает свои
временные файлы старше часа, оставшиеся после аварийного завершения.
Для передачи медиа действует deadline 10 минут; обычные запросы сохраняют 5 секунд.

Миграция `00005_publications.sql` добавляет посты, медиа и таблицу `subscriptions`.
Начиная с этапа 4 выдача доступа выполняется платёжным сервисом после серверной
проверки ЮKassa; runtime API и worker имеют необходимые права записи. Интеграционные тесты создают тестовые подписки непосредственно в
изолированной БД: нужный/старший, младший, чужой, будущий, истёкший и отозванный
уровень. Тесты с настоящим MinIO проверяют приватность bucket, Range/HEAD, оригиналы,
миниатюры, границу 100 МиБ и очистку. Запуск — `make test-integration`.

Браузерные тесты публикаций запускаются отдельно от auth, на свежем тестовом
Compose-стеке, чтобы обе группы использовали обычные production-лимиты:

```sh
# В корне; отдельные volumes и порты, без изменения основного окружения.
APP_PORT=18080 MAILPIT_PORT=18025 APP_ORIGIN=http://localhost:18080 \
  docker compose -p etheyl-posts-tests up --build --wait
cd frontend
E2E_BASE_URL=http://localhost:18080 MAILPIT_URL=http://localhost:18025 \
  pnpm test:e2e:publications
```

Оба проекта Playwright (desktop/mobile) проверяют черновик, все четыре вида файлов,
настоящее воспроизведение аудио/видео, скачивание вложения, публикацию, изменение
доступа, отсутствие закрытого текста в SSR и запрет прямых запросов к файлам.
В CI группы auth и publications получают отдельные свежие Compose-окружения.


## Этап 4: тестовая оплата и подписки

Реализованы оформление через ЮKassa, серверная сверка результата, доступ к закрытым
постам, календарный месяц, явное согласие на автопродление, очередь worker,
фиксированная цена, смена уровня со следующего периода, отмена, история и письмо
при отказе. [Настройка магазина, HTTPS/webhook, гарантии, ручная сверка и проверки](docs/billing.md).

В `.env` нужны `YOOKASSA_SHOP_ID` и `YOOKASSA_API_KEY` тестового магазина.
Обе пустые позволяют запуск без оплаты; только одна заполненная — ошибка настройки.
После изменения переменных: `docker compose up --build --wait`.
Управление находится в `/account/subscriptions`, история — `/account/payments`.
Локальный worker сверяет результат и без внешнего webhook; для входящих уведомлений
нужен доступный ЮKassa HTTPS endpoint. CI добавляет отдельную browser-группу `billing`.


## Этап 5: лента, обсуждения и аналитика

Персональная лента — `/account/feed`, обсуждения — под опубликованными постами,
аналитика автора — `/account/analytics`. Доступ и пагинация проверяются Go API.
Лайки идемпотентны, комментарии плоские и экранируются как обычный текст.
Аналитика считает только подтверждённые тестовые платежи в UTC и отдельно показывает
подписки с активным оплаченным доступом. [Правила, схема доступа и проверки](docs/social.md).

CI дополнен группой `social`: лента → чтение закрытого поста → лайки/комментарии →
контрольные платежи и график аналитики, на desktop и mobile. Для этой группы нужны
свежий отдельный Compose и `E2E_SOCIAL_PROJECT`; публичного API выдачи grants нет.
